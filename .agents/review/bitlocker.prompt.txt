WHERE DEFECTS ARE MOST LIKELY - use as attention hints, not as a checklist, and
do not report an item merely because it appears here:
- Secret handling. A BitLocker recovery key decrypts an entire disk. It must
  never reach an audit record, a log line, an error message, or a trace. Check
  every path a recovery password could escape through, including exception
  messages and PowerShell error streams.
- Fail-closed behaviour. An unreachable or misconfigured source must be an
  ERROR, never an empty result: "no key exists" and "I could not look" must not
  render identically to an operator on a live recovery call.
- Authorization. The page must deny a direct route hit, not merely hide a nav
  link. The module policy is fail-closed and the module is disabled by default.
- The reveal path. Searching returns masked rows; revealing a key is the audited
  security event. Check that one audited reveal cannot disclose more than one
  key, and that reveal state cannot leak across searches.
- SQL and LDAP injection, including LIKE-pattern escaping and LDAP filter
  escaping.
- PowerShell runspace lifetime: leaks on failure paths, and disposal ordering.
- Resource limits: an unbounded result set pulled into the web process.
- Partial-failure reporting: whether a degraded search can be mistaken for a
  complete one.
- Concurrency, given this is a Blazor Server circuit with scoped services.
