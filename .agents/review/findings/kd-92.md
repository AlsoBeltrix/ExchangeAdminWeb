# kd-92: Group Management's manager notice reads objectClass as a list of characters, so it never sends and files a Failed row on every change

**Severity**: HIGH - sweep item 9. `Services/GroupManagementService.cs` about 324-326 reads objectClass `as IEnumerable` and
looks for an element equal to "user"; the AD module returns a string (this file reads it so at about 1211), which enumerates
as characters. Every successful add, remove or batch logs "managedBy ... is not a user (objectClass: u,s,e,r)", files a
Failed `<action>_ManagerNotNotified` row (`Components/Pages/GroupManagement.razor` about 870-872), sends no mail, and paid a
secret read and a fresh AD session anyway. A group with no manager files the Failed row too. The tests only scan source text.
**Status**: Fixed on branch, verified; closes on guard proof
**Branch**: `fix/sweep-a` (worktree `D:\source\ExchangeAdminWeb-wt\sweep-a`, from master `cfd011da`)
**Commit**: the commit that adds this line (its SHA in the implementer's hand-back) | **Reviewer**: implementer (candidate)

## Approach

- Read the value as a string (as about 1211 does, or SelfGrantDirectory's ObjectClassOf); file no Failed row for a group with
  no manager; a real behaviour test with a stand-in returning a string; mutation: the IEnumerable read restored. Note for the
  owner: once it sends, managers get the administrator template with the operator's IP - the sweep flags the template choice
  (item 9 "Also"); do not change the template here, record it.

## The fix (implementer, 2026-10-30; branch `fix/sweep-a` from master `cfd011da`)

- **`Services/GroupManagementService.cs` `GetGroupManagerAsync`**: the manager's class is read as the AD module returns
  it - a string, the object's most specific class, as this same file reads it in `ResolveMemberForWrite` - through
  `SelfGrantDirectory.ObjectClassOf` (made `internal` for it; its rule unchanged): a string as it is, the multi-valued
  attribute as its last value. Only "user" is a recipient, as before. The refusal's warning now names the one class
  ("objectClass: group"), not a list of characters.
- **`Components/Pages/GroupManagement.razor` `NotifyGroupManagerAsync`**: a group whose `managedBy` is empty is not a
  failure - one Information line ("Group <name> names no manager (managedBy is empty); no change summary was sent for
  <action>.") and no audit row. The service already returned before any credential fetch or directory read for it. A
  `managedBy` that does not resolve, names no mailbox, or names something other than a user, and a summary no recipient
  accepted, still file the Failed `<action>_ManagerNotNotified` row they always did. Edited in place: the page keeps its
  1158 lines, every edit is inside `@code` below the lowest registered control (315), so no ClickGateRegistry or
  ProgressRegistry entry moves.
- **`Modules/ModuleCatalog.cs`**: Group Management 2.16.0 -> 2.16.1 (module-scoped behaviour). `SelfGrantDirectory` is
  shared, but only its visibility changed; the base app version bump is already owed (2.36.0) for the stream.

Not changed, by instruction: the notice's template (below).

## Found while doing it, not fixed

- **The template, now live (the sweep's item 9 "Also"; recorded, not changed by instruction).** With the class read right
  the notice sends, and a manager receives `EmailService.SendModuleNotificationAsync`'s administrator template - subject
  "[Admin] <action> - SUCCESS - Ticket #<ticket>", the operator's IP address among the rows - not gated by
  `Email:NotifyUsersOnPermissionGrant`. Whether a manager should get that wording, and whether the switch should gate it,
  is the owner's to decide.
- **Each notice still opens a fresh AD session** (`CreateDirectoryRunspace`, a module import, one Get-ADObject) after the
  change, a few seconds the operator does not wait on beyond the change itself; the module credential behind it is a
  secret-store read each time unless kd-88's credential window (a later commit on this branch) keeps it. Not changed.
- **`inetOrgPerson`** managers are refused as before (their class is not "user"); recorded only.
