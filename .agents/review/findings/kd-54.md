### As written before the code (branch `fix/psl10-a2y` from `622fe2cc`, kd-53 on it; no merge of master)

**Verified.** `Components/Pages/AdminBulkJobs.razor` `RemoveJob`: `WriteAudit("AdminBulkJobs_RemoveJob", job, removed)` - on a
false it files Failed with no error and no refusal fields, so the row says a removal did not happen and not why, while the
banner guesses ("it may still be running"). `BulkJobService.DeleteJob` returns false for a job that is gone, one whose
module does not match (impossible here - the page passes the job's own) and one the repository would not delete, which is
every job not in a terminal state (`BulkJobRepository.Delete` 316-335: `WHERE id = $id AND status IN (Completed,
Cancelled, Interrupted)`).

**The change.**
1. On a false the page reads the job back (`BulkJobs.GetJob`, a read, on the failure path only) and files the reason it
   finds: "The job was not removed: it no longer exists." when the read answers nothing, "The job was not removed: it has
   not finished." otherwise - and `refusedAt` "JobState" with `mutationAttempted` false, kd-32's label and fields for the
   same class of refusal on the cancel. A removal that happened is unchanged, and its row carries no such field.
2. The banner says that reason instead of guessing.
3. No service change: `DeleteJob` keeps its bool.
4. Tests in `AdminBulkJobsCancelAuditTests` (the page's audit rows; its summary widens to the removal): a finished job
   removed - Success, no refusal fields; a running job and a job already gone - Failed, that reason, the fields, the store
   unchanged. Mutations: the reason dropped; the refusal fields dropped; the state read dropped so both reasons read "has
   not finished".
5. Admin Bulk Jobs' 1.2.0 note (kd-53, this batch) gains the line; no second bump.
