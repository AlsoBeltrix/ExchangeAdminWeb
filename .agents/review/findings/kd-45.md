### Verification

All five are true, and all five are the same line: `string.IsNullOrWhiteSpace(ticket)`, which kd-24 and kd-48 showed
answers false for a control-only or zero-width ticket while a dormant ServiceNow passes it.

- `Components/Pages/RiskyUsers.razor:869` - `ExecuteActionAsync` (`:816`), presence then validation (`:875`); the
  refusal is `Refuse("A ticket number is required.", "Ticket number missing")`, before `notifyAdmins` and the write.
- `Components/Pages/IntuneDevices.razor:1026` - `ExecuteActionAsync`, the same shape, same refusal wording.
- `Services/MessageTraceExportListing.cs:175` - `TryDownloadAsync` refuses before the job is resolved or the file is
  read; the ticket is never validated (plan D2), so this presence check is the whole of the requirement there.
- `Services/MigrationService.cs:1002` and `:1011` - `RefusesSingleCreate` / `RefusesBulkCreate`, the last clause of
  each refusal ternary.
- `Services/EmergencyDisableService.cs:186` - `DisableAsync`'s first act, before the protected-principal check and
  every backend; it audits the refusal through `LogRefusal`.

`Services/AccountLockoutRemediationService.cs:314` has the same shape and is **left alone**: that module's findings are
deferred by the owner (2026-10-19), so it is out of the released scope. Nothing else in the app still tests ticket
presence by hand - swept with `grep` over `Components/` and `Services/` for `IsNullOrWhiteSpace` on a ticket name.

### What changes

Two commits, by file class, as dispatched: the two pages, then the three services. Each site becomes
`!TicketPresence.IsPresent(ticket)` (the Migration pair keep their ternary shape), one line for one line - the pages
are line-keyed and nothing moves, and the services' call sites are untouched. No message changes: each site keeps the
refusal wording it had, so nothing an operator reads or a test pins moves.

- Guards, per site and all driving the real code: RiskyUsers and IntuneDevices by reflection over the compiled page
  (the kd-4 pattern), each with its service's counting Graph-factory seam, so "never reached the write" is counted
  rather than inferred; `MessageTraceExportListingTests`' existing blank-ticket theory gains the invisible cases, and
  its read-spy already proves the file is never touched; `MigrationService`'s two pure refusal functions directly;
  `EmergencyDisableService.DisableAsync` through the file's own `CreateService` harness, asserting the audited
  refusal.
- Mutation, per commit: one site back to `IsNullOrWhiteSpace`.
- Module bumps, one minor step each from this branch's values: RiskyUsers, IntuneDevices (pages commit); MessageTrace,
  Migration, EmergencyDisable (services commit). No base bump - `TicketPresence` itself is unchanged here.
