and a dormant `ServiceNowService.ValidateTicketAsync` (`Services/ServiceNowService.cs:57-65`) passes it, so every presence

`MfaReset`. The same test sits in `DhcpAuthorization.RemoveServer` (`:385`) and in the shared policy layer,
`TicketValidationService.ValidateAsync` (`:78`, which BitLocker and Cloud Password Reset go through). With ServiceNow
enabled the pattern check (`ServiceNowService.cs:85`) already refuses one.

  and spaces included (decision 2026-08-31). `IsPresent`, and `Refusal` - the same "Ticket number is required" result
  the pages' checks already flow through.
- Every gate above uses it. `ConferenceRoomService.RequireTicket` forwards to it, so the Conference Rooms page - which
  another worktree is editing - and the processor are unchanged; the three kd-18 `MissingTicket` helpers are removed
  and their call sites name `TicketPresence.Refusal`; the M365, Named Locations, `RemoveServer` and
  `TicketValidationService` tests name `TicketPresence.IsPresent`.
- Not changed here, reported to the supervisor instead: the presence checks that predate this branch in other modules -
  `RiskyUsers.razor:870`, `IntuneDevices.razor:1026`, `EmergencyDisableService.cs:186` (the psl-10 worktree is editing
