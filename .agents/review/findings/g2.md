## Evidence (master 6758e796)

- `Services/M365GroupManagementService.cs` `CheckProtectedAsync`: a blank identity returned "proceed"; a resolution of
  NotFound returned "proceed" with no check.
- `RemoveDirectoryObjectAsync` checked `identityForCheck` (UPN or mail from the page) and deleted `objectId`.
- `AddDirectoryObjectAsync` checked the typed string, then resolved it (`ResolveDirectoryObjectIdAsync`), which passes a
  typed GUID through as the object id after the gate ran on the string.

## Fix (as landed)

- Add: a blank identity refuses; the identity is resolved to its object id first, then that object is checked, then the
  same id is written.
- Remove: a blank object id refuses; the object id that is deleted is the one checked.
- The check is the shared Entra-user gate (`ProtectedPrincipalServicing.ForCloudUserAsync`, see g1b), so NotFound in
  Active Directory and Exchange no longer means "proceed": the object is bound by its on-premises SID or refused.
- By object type, decided from Graph (`GET /users/{id}?$select=id` under the module's own client, which already needs
  `User.Read.All` to resolve a typed name): a user (200) is checked; an object Graph holds no user for (404 - a service
  principal owner, a device, a group, or no object at all) has no user to protect and proceeds, logged ("... is not a
  user in the directory - no user to protect; proceeding"); any other answer refuses as unavailable. An add resolved
  by UPN or address is already known to be a user and is not read again; a typed GUID is.
- Messages are the module's own and unchanged: "Identity is ambiguous - matches multiple AD users.", "Protection check
  unavailable. Cannot verify if this member is protected." (also the blank-identity refusal), "Protection check failed:
  {reason}", "This member is a protected principal. Operation not permitted.", "Protection check error: {message}".
- Test seam: `GraphClientForTests` on the service, so the tests run the real gate over a stand-in Graph.

## Tests

`CloudUserProtectionCallerTests`: adding the protected user by UPN checks the object Graph resolved and refuses with no
POST; removing it checks the object id it deletes; blank add and blank remove refuse with no Graph call; an identity
Graph does not find never proceeds; an object Graph holds no user for is removed with no protection read; an object
Graph cannot classify (403) refuses. Changed: `M365GroupManagementServiceTests` (12) run over a stand-in Graph and also
assert no write was sent; `M365GroupManagementServicerTests` allow cases now assert the write and the note (they passed
before on an exception from an unconfigured Graph client, which now comes before the gate); the ticket-gate control
expects the unconfigured-client error for every write. `ProtectionCheckCallSiteTests` row S9 removed (the gate's own
row covers it).
