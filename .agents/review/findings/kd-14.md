**Severity**: LOW - a cancelled read is shown as a failed one. `Services/RecipientLookupService.cs` about 169 and 197: both catches catch `OperationCanceledException` and use raw `ex.Message` (the aud-a23l class the aud-a68 (2) fix applied to the statistics read only).

## Evidence

At `44fb74aa`. Trigger: the operator cancels during the location or size read. Predicted failure: a warning worded as a failure, with the cmdlet prefix.

## Approach (to be written by the implementing agent before code)

- Both catches exclude cancellation and use the aud-a23i error-text helper, as (2) did; tests mirror (2); mutation: one catch back to raw.

### As implemented (implementer, 2026-10-23, branch `fix/a68-kd2`; lines at `a63b62bd`)

- `Services/RecipientLookupService.cs` the location catch (166-170) and the on-premises size catch (194-198): `catch
  (Exception ex) when (!IsCancellation(ex))`, and the warning through `ResolveFailure(ex).primary` (aud-a23i's helper),
  its words otherwise unchanged ("Could not determine mailbox location: <reason>", "Could not retrieve on-premises
  mailbox size: <reason>"). A cancellation now leaves `GetRecipientInfoAsync`, as aud-a23g's rule has a read's catch let it,
  and the page's `RunLookup` (aud-a68 (4)) shows it as the lookup's error, audits it Failed and ends the activity with it.
- What normally reaches these catches is a message the base composed (no prefix); what reaches them raw is a throw
  outside the base's wrappers - the module credential read, the throttle. So the helper covers that kind, and the
  cancellation is the change an operator would see.
- Only a real cancellation is let through: the credential read under both (`DelineaService.GetCredentialsBySecretIdAsync`,
  `Services/DelineaService.cs` 219-229) rethrows an `OperationCanceledException` only when its token was cancelled and turns
  any other failure, an HTTP timeout's `TaskCanceledException` included, into "could not be retrieved", so a slow vault is
  still a warning beside the rest of the lookup, as before.
- Test stand-in (`ExchangeAdminWeb.Tests/MigrationStubExchange.cs`): the credential seam takes its purpose -
  `Failures["OnPrem Credentials <purpose>"]`, an exception thrown as it is or a string as an `InvalidOperationException` -
  so one read's credentials fail without the other's ("on-prem mailbox location check", "on-prem mailbox size check");
  and `StopFailure(message)`, a real ActionPreferenceStopException, moves here from `RecipientLookupFailureTests`
  (aud-a68 (4)) for kd-15 to share.
- aud-a68 part 1's "the size read throws as a whole" case reached the size catch with a cancellation
  (`OnPremStatisticsCancelled`); kd-14 lets a cancellation through, so that case now reaches it with the size read's
  credentials failing - a throw that is not one - and the cancellation is kd-14's own test.
- Tests (`RecipientLookupFailureTests`, mirroring (2)): a cancelled location read and a cancelled on-premises size read
  leave the service and raise no warning; a location read and a size read that fail with PowerShell's Stop text are a
  warning in the error's own words. Mutation: the location catch back to raw (the record's); extras: the size catch
  raw; each catch taking a cancellation again.
- No module bump: Recipient Lookup 1.1.0 is unreleased (this branch's, merged at `44fb74aa`, not deployed).
