# kd-12: ClickGateSource.BlankComments blanks code between a "/*" and "*/" that sit inside string literals

**Severity**: LOW - latent test-infrastructure defect. `ExchangeAdminWeb.Tests/ClickGateSource.cs` about 61-72 (base): the comment-blanking regex does not know about string literals, so a page containing `"/*"` in a string would have real code blanked. No page has such a literal today.
**Status**: Verified on branch; awaiting merge and codex review
**Branch**: `fix/kd-misc` (worktree `D:\source\ExchangeAdminWeb-wt\kd-misc`, continuing from `e3cc2d7a`)
**Commit**: -
**Reviewer**: implementer (kd-misc agent, candidate; not yet confirmed by the supervisor)

## Evidence

At `e3cc2d7a`. Trigger: a string literal containing `/*`. Predicted failure: code between it and the next `*/` disappears from every guard's view.

## Approach

Re-read at `4ca37cdd` (kd-11's commit):

- `ExchangeAdminWeb.Tests/ClickGateSource.cs:61-72` - `BlankComments(string source)`: three regexes,
  `@"@\*.*?\*@"` and `@"/\*.*?\*/"` (both Singleline) and `@"(?m)(?<=^[^""'\r\n]*)//[^\r\n]*"`. None knows a string
  literal: a `"/*"` blanks to the next `*/` wherever it is, and a line comment is blanked only when no quote opens
  earlier on its line, so a comment after a string is left in, readable as code.
- It is `Text` for every ClickGate scan (the constructor, `:24`), and is called directly by
  `ClickGateTests` (two markup fixtures) and `GroupMemberNestingProtectionTests` (a page).
- The Roslyn-backed comment view the record points at already exists: `RazorSyntax.CommentsBlanked` (C# comment trivia
  inside @code regions; Razor comments in markup; literals intact; offsets kept). Two things stop it being a drop-in:
  `RazorSyntax.Parse` reads text with no @code block as C# whole (the ClickGate markup fixtures have none), and it does
  not treat a markup `@{ }` block as C#, where the regex did blank comments (Components/Pages/MessageTrace.razor:405-410
  has three).

What changes:

1. `ClickGateSource.BlankComments` is `RazorSyntax.ComponentCommentsBlanked(source)`: the same view, reading its input
   as a component whatever it holds (a fragment with no @code block is all markup), and also blanking the comment
   trivia of each markup `@{ }` block, lexed with Roslyn tokens from its brace to the matching one. `RazorSyntax`'s
   existing `CommentsBlanked`, which the progress guards read, is unchanged in behaviour (its body moved into a shared
   private helper).
2. Measured on every page before relying on it: a throwaway comparison (not committed) of the old and new views line by
   line across `Components/Pages` - see Guard proof.

Declared files: `ExchangeAdminWeb.Tests/ClickGateSource.cs`, `ExchangeAdminWeb.Tests/RazorSyntax.cs`,
`ExchangeAdminWeb.Tests/ClickGateTests.cs` (the guard), this record. No module version: test infrastructure only.

Mutation: the regex restored.

## Guard proof

**What changed on the real pages:** the comparison found **36 lines** where the views differ, all in @code: each is a
line whose trailing `//` comment follows a quote (`MailboxPermissions.razor:528` and `:744`, `CalendarPermissions.razor:505`
and `:687`, `AdminEventLog.razor:1043`, and 31 in `Migration.razor`). Checked line by line: on every one the new view is
the raw line up to the comment, and what it blanks begins `//` - the comment the regex left in. **No line kept by the
new view was blanked by the old** (the first draft kept the three MessageTrace `@{ }` comments; the code-block pass
closed that before this was recorded).

**Changed results (the brief's ask): none.** `ClickGate`, `GroupMemberNesting` and `MigrationStatusPage` filters, 473
tests, compared test by test from TRX before and after: identical, all passed. The same filters with `ProgressRegistry`
and the Razor-syntax tests after: 516 passed.

`BlankCommentsBlanksCommentsAndLeavesWhatIsInsideStringLiterals` - a component fixture with `"/*"` and `"*/"` literals
around real code, a trailing comment after a brace and one after a quote, a block comment, a Razor comment and a markup
`@{ }` block's comment, each naming `isBusy = true;`. The view must keep the length and line count, keep the code
between the literals and the literals themselves, keep the markup, leave exactly one `isBusy = true;`, and hold no
comment text.
