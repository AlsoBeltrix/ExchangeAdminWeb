# kd-73: two cancel checks missing after kd-59 - between Message Trace's cloud search windows, and before Conference Rooms' first write

**Severity**: LOW - the operator's cancel is honoured a little late or not at all at two points. (1) Message Trace's chunked
cloud search does not check the activity's token between windows, so a cancelled search is filed only once the cloud
windows finish (about ten seconds at most). (2) In Conference Rooms a cancel that lands after the last pre-write credential
fetch and before `Set-Place` is not noticed; one token check immediately before `Set-Place` closes it, and keeps kd-59's rule
that nothing after the first write takes a token.
**Status**: Fixed on `fix/kd73-kd74` - (1) Message Trace and (2) Conference Rooms, one commit each; verified on branch;
awaiting merge; unreviewed until the single final codex-commercial review

## Record correction

The severity line says a cancelled search "is filed only once the cloud windows finish". That holds for a cancel during
the on-premises half's credential fetch. A cancel landing after that fetch was not filed as a cancel at all: nothing else
looked at the token, so the search ran every window and was filed as one that ran to its end. Fixed by the same check
for a cancel with a window still to run; a search of one window, or a cancel during the last, is still not looked at -
see (1)'s "Unchanged, on purpose". Left as written above; noted here. LOW stands: the search is a read.
