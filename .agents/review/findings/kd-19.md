## Evidence

At `881b8d5b`. Trigger: two quick Manage clicks on different groups. Predicted failure: a member of A shown under B; Remove acts on B with A's member identity, or is refused confusingly.

## Approach

Re-read at `aed153c9` (this branch; `SelfServiceGroups.razor` is unchanged on master since).

### Verification

True, and reachable from ordinary clicks. Both Manage members buttons (`:128`, `:179`) are enabled in the same browse
render, and `SelectGroup` (`:542-549`) has no server-side refusal, so two clicks on different groups within one round
trip both run. `LoadMembers` (`:566-608`) snapshots its group (`:574`) but publishes `groupMembers` (`:596`) and
`memberLoadError` (`:601`) and lowers `isLoadingMembers` (`:605`) whatever has happened since; whichever read finishes
last fills the table, the Remove buttons act on `selected` (the second group), and the first load's `finally` re-enables
the manage view while the second is still reading. (The kd-8 `ShowFor` guard does not cover this: it is on the
operations, and this is the load.)

### What changes

- `SelectGroup` refuses at entry while the manage scope is busy - `if (IsManageBusy) return;`, the predicate the two
  Manage members buttons already carry - so the server agrees with the gate one round trip later. `isLoadingMembers` is
  part of that predicate and `LoadMembers` raises it before its first await, so a second Manage click during the first
  load is refused and nothing of the first group's can be shown under the second.
- `LoadMembers` publishes only while its group is still the one shown. Not by `ReferenceEquals(selected, group)` after
  the await: `ClickGateRegistry` registers `selected` as a field `LoadMembers` must not read after its first await (the
  tier-1 null-dereference obligation), and that matcher cannot tell a comparison from a dereference. A monotonic
  `memberLoadToken` instead, `GroupManagement.SelectGroup`'s shape: every load takes the next token, `BackToGroups` -
  the only other writer of `selected` - advances it, and a load publishes `groupMembers` and `memberLoadError` only
  while its token is still current. The activity completes from a local, so it still reports this load's outcome.
- `isLoadingMembers` is still lowered unconditionally in the `finally`. A token-guarded lowering would stick the flag
  true when `BackToGroups` advances the token mid-load, and the flag is a member of the view's predicate - the trap the
  GroupManagement note records.
- Line keys: every registered line is in markup at 398 or earlier and every edit is in `@code` below 453, so only
  `ExpectedLineCount` moves. The registry remark and the `ShowFor` comment that call the Manage gate markup-only are
  corrected in place.
- Guard: `SelfServiceGroupMemberLoadTests` holds a real member read at the credential fetch (a gated vault stand-in
  behind the real `SelfServiceGroupService`, `ModuleCredentialService` and `DelineaService`, so nothing reaches a
  directory) and drives `SelectGroup` / `BackToGroups` by reflection.
- Mutations: the `SelectGroup` guard removed; the token test removed.
- Module `SelfServiceGroups` 1.12.0 -> 1.13.0; no base app bump.

## Guard proof

`SelfServiceGroupMemberLoadTests` (3) holds the first group's real member read at the credential fetch: a vault
stand-in behind the real `DelineaService` (bootstrap credential injected through its test constructor, so the host's
credential store is not read) holds the first request and then answers every request with a server error, so each load
ends refused for want of a credential and no directory is touched.

- `ASecondManageClickWhileTheFirstGroupIsLoading_IsRefused_AndTheFirstGroupGetsItsOwnOutcome`: while the first load is
  held, `SelectGroup(second)` completes at once and the first group stays selected; once released, the first load
  publishes its own failure into its own view (the control), the view is no longer busy, and after Back the second
  group opens.
- `ALoadThatFinishesAfterTheOperatorWentBack_PublishesNothing`: Back while the load is held; it finishes with no
  `memberLoadError`, an empty list, and `isLoadingMembers` lowered.
- `BothOfALoadsPublishesWaitForItsToken`: the success half cannot be driven without a directory, so its guard is pinned
  as text.

## Known gaps

- `isLoadingMembers` is still lowered by whichever load finishes, current or not. With `SelectGroup` refusing while
  busy, two loads overlap only if a membership operation starts during a reload, and the operations refuse only on
  `isChanging` (their registered guards), so that needs a programmatic click; the older load then re-enables the view
  while the newer reads. Its results are discarded by the token. A token-guarded lowering would trade this for a
  flag that `BackToGroups` could strand.
- No live check: no directory call was made; rendering is not exercised (no bUnit harness).
