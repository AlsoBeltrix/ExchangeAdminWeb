# kd-60: a countdown range in test stand-ins emits objects where none were asked for

**Severity**: LOW - test infrastructure, and a silent one: a stand-in asked for "none" answered Found. `1..0` in
PowerShell counts DOWN and yields two values, so a stand-in emitting `1..$count` objects cannot represent an empty
answer. Found and fixed in the psl-11 helper during kd-55 (now a count-controlled `for`); the same idiom may appear in
other stand-ins, each of which would quietly answer "found" where a test means "not found".
**Status**: Closed 2026-10-27 - swept by the supervisor; the kd-55 site was the only one that could count down
**Branch**: -
**Commit**: -
**Reviewer**: implementer (psl10-a2y agent, candidate; not yet confirmed by the supervisor)

## Evidence

At `595a74ba`; the kd-55 record carries the case that caught it.

## Approach

- Sweep the test stand-ins for `1\.\.` over a count that can be zero and replace each with a count-controlled loop; for
  every one found, add or check a not-found case, because the defect is invisible without one; mutation: the countdown
  restored at one site, which must fail that site's not-found test.

## Guard proof

Sweep 2026-10-27 over every `.ps1`, `.psm1` and `.cs` file (embedded stand-in scripts included) for a range whose
lower bound is 1 and whose upper bound is a variable or expression. Three sites, none reachable with zero:
`ExchangeAdminWeb.Tests/MigrationMailboxLoadTests.cs` 245 (`$count` is 1205 or 1000);
`tests/ps/CoverageFloor.Tests.ps1` 27 (`$Total` is 1000 or 10000 at every call); `Services/AccountLockoutRemediationService.cs`
990 (`1..($cols.Count - 1)` behind a `$cols.Count -lt 5` guard, so at least `1..4`). The kd-55 helper is already a
count-controlled `for`. No code change; no mutation to run.
