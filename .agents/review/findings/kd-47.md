### Verification

True, and the cause is now measured rather than guessed. `TheConsumer_GivenItsFolderRemoved_CreatesItAgain_AndWritesTheNextEntry`
(`ExchangeAdminWeb.Tests/ExtendedLogServiceTests.cs:567`) retries `Directory.Delete(folder, recursive: true)` through a
local `TryDelete` (`:591-602`) that catches `IOException` only. The appender releases its lock by moving the lock file
aside to `<log>.lock.<guid>` and deleting it (`Services/JsonlFileAppender.cs:184-205`), and its own comment records
that a delete leaves the name delete-pending for a moment. A delete-pending file in the folder makes
`Directory.Delete` throw `UnauthorizedAccessException` ("Access to the path '...lock.<guid>' is denied"), which the
catch lets out, failing the test - the failure seen on this branch's DHCP run. Probed on this host: a file held open
with no sharing gives a sharing violation (`IOException`, caught); a file made delete-pending through its handle
(`SetFileInformationByHandle`, FileDispositionInfo) gives exactly the failure's `UnauthorizedAccessException`; once the
handle closes, the delete succeeds.
