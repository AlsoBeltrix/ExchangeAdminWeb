## Approach

Re-read at `0269af30` (kd-30's commit):

- `ExchangeAdminWeb.Tests/ClickGateSource.cs:194` - in `WalkCodeBody`, `else if (c == '<' && (char.IsLetter(next) || next == '/'))`
  treats every "<" followed by a letter at code level as a tag: `List<string>` and `row.Count<limit` open an element that
  never closes, `EndOfElement` returns the end of the file, and the walk stops - every comment after them in the body is
  left readable.
- `:227-268` - `EndOfElement`'s search for the matching end tag counts any `<name` of the same name, so `<b>@(a<b ? x : y)</b>`
  reads `<b ` as a nested `<b>` and never closes either.
- `:80` - `BlankComments` blanks C#, Razor and markup-code-block comments; an HTML comment (`<!-- -->`) anywhere in the
  markup was text, and so was the prose some of them carry.

What changes:

1. **A tag starts only where a statement can and only with a tag's shape.** `WalkCodeBody` tracks whether a statement can
   begin (the body's start, after `{`, `}`, `;` or a label's `:`, after a skipped element or `@:` line, or right after a
   template's `@`); `IsTagShape` requires an optional end-tag slash, a letter-led name, then whitespace, `>` or `/`.
   `count<limit` (no shape, no statement start), `List<string>` and `row.Count<b ?` (shape, but mid-expression) are C#.
2. **`EndOfElement` reads C# inside an element's content as C#:** a `@( ... )` expression and a construct's `( ... )` header
   are skipped with Roslyn tokens, and a nested same-name tag counts only with a tag's shape.
3. **HTML comments are blanked in the markup** (`BlankHtmlComments`, before the control-flow pass, so the walker skips
   them): a `<!--` outside the @code regions through its `-->`; one that never closes is left alone. A `"<!-- -->"` string
   in @code is untouched.
