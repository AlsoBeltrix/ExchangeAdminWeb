### Approach

Confirmed on both pages: `SubmitSingle` (`Components/Pages/MailboxPermissions.razor` 394, `CalendarPermissions.razor` 374) and
`ProcessBulk` (Mailbox 587, Calendar 548) ask `ServiceNow.ValidateTicketAsync` with no presence check, and
`Services/ServiceNowService.cs` 57-65 answers valid for every ticket while the integration is off. The ticket is captured at
entry (Mailbox 364 / 562, Calendar 351 / 528); the buttons' clauses are the only presence enforcement.

- Each check becomes `TicketPresence.Refusal(ticket) ?? await ServiceNow.ValidateTicketAsync(ticket)`, in place: a ticket
  with nothing in it that identifies one gets the refusal `ServiceNowService` gives a blank ticket when enabled ("Ticket
  number is required"), so it flows into the existing refusal branch, which kd-40 makes record its row. ServiceNow is asked
  only about a ticket that is present; the `ServiceNow.ValidateTicketAsync(` call ProgressRegistry pins stays in each body.
  Both pages stay 808 and 762 lines.
- **The rule is kd-24's, not these pages' own** (supervisor's instruction, 2026-10-26; `Services/TicketPresence.cs` and its
  tests, both taken from master byte-identical, `af1e92f42e03d8ad4c14557874972caf` and
  `89e901a151fe8903a3d49de264eae55e`). The Mailbox half, merged at `b7440dce`, had shipped its own copy -
  `SelfGrantRefusalRecord.MissingTicket`, written before kd-24 landed - so the app carried two rules for one question. That
  helper is deleted and both pages now call `TicketPresence.Refusal`. The rules agreed on everything these tests ask, and
  kd-24's is the stricter: it refuses a ticket with a control character ANYWHERE in it ("INC0042\x07"), where the deleted one
  passed it for the printable characters beside it. So the Mailbox page is tightened here too, and both pages follow kd-48 if
  it tightens the shared rule further.
- Tests (`PermissionPagesSelfGrantTests`): a single change and a bulk run with a blank, a white-space and a control-only
  ticket - refused, one Failed row with `refusedAt` TicketValidation and `mutationAttempted` false, nothing sent to Exchange
  and the file never read. `TicketPresenceTests` (from master) holds the rule itself. Mutation per page and per handler: the
  presence check removed (`TicketPresence.Refusal(ticket) ??` dropped).
