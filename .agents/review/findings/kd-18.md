The existing invalid-ticket refusal rows on all three carry no `refusedAt` / `mutationAttempted`.

### What changes (each page)

- The ticket check becomes `MissingTicket(ticket) ?? await ServiceNow.ValidateTicketAsync(ticket)`: a page-local static
  that gives a blank ticket the refusal `ServiceNowService` itself gives one when enabled ("Ticket number is
  required"), so it flows into the existing refusal branch - banner "Ticket validation failed: ...", one Failed audit
  row, return - ahead of everything else the handler does, as before. ServiceNow is asked only about a ticket that is
  present, and the `ServiceNow.ValidateTicketAsync(` text stays in each body. (kd-24, next on this branch, replaces
  the presence test itself with one shared rule; this record does not anticipate it.)
- Every ticket refusal row - blank and invalid - gains `refusedAt` "TicketValidation" and `mutationAttempted` false:
  in the row's own extra on `AddMember` / `RemoveMember`, through an optional `refusedAt` on `GroupManagement`'s
  `AuditBatch`, as an extra on `DhcpAuthorization`'s row, and through `LogMfaResetAction`'s `extra`.
- Line keys: `GroupManagement` and `DhcpAuthorization` are registered (keys up to 274 and 121; `@code` from 318 and
  132), so only their `ExpectedLineCount` moves, by the diff map. `MfaReset` is not converted. `ProgressRegistry` is
  method-keyed and every named call survives.
- Guard, per page: a reflection-driven test of the handlers with a dormant ServiceNow, a refusing authorization
  service as the next step, and the page's audit log - a blank ticket refused with the row and the authorization never
  asked; a ticket ServiceNow rejects refused the same; the control reaching the authorization check.
- Mutation, per page: the presence check removed (`MissingTicket` answering null).
- Module bumps, one minor step each: `GroupManagement`, `DhcpAuthorization`, `MfaReset`; no base app bump.
