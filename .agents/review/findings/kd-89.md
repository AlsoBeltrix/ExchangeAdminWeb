# kd-89: Exchange Online's "not found" arrives as bare text and is no longer recognised, so Migration checks and on-premises permission targets are refused

**Severity**: HIGH - sweep item 2. Since aud-a23h/a23o a not-found is recognised only from the error record's structure
(`Services/ExchangeServiceBase.cs` about 516: `CategoryInfo.Category == ObjectNotFound || NamesNotFound(Reason)`), and a thrown
error skips the identifier test (about 520). This tenant's module throws its not-found as bare text - prod `app-20261012.log`
12:08:23 and dev `app-20261023.log` 04:35:13: `RuntimeException: ||The operation couldn't be performed because object '...'
couldn't be found on '...'` over a plain `System.Exception`. The code says so at about 488-491: "ASSUMPTION, unverified (no
live call)". Likely effect: every Migration eligibility check reads "Could not be determined" (`MigrationService.cs` about
90-93); every Mailbox / Calendar Permissions / Out of Office change on an on-premises mailbox is refused at the location
read (about 882-885); approval of a mailbox with its own batch refuses (`MigrationService.cs` about 1360); a Room Finder row
for a building without a list refuses; Recipient Lookup says "Could not be read" for an unknown address.
**Status**: Fixed on branch, verified; closes on guard proof

- Also accept Exchange's own sentence, as `Services/ExchangeIdentityResolver.cs` has since July (`NotFoundFragment =

## The fix (implementer, 2026-10-30; branch `fix/sweep-a` from master `cfd011da`)

The logged shape, read from the logs (read-only): prod `app-20261012.log` 12:08:23 (Recipient Lookup's Get-Recipient for an
unknown address) and dev `app-20261023.log` 04:35:13 (the old build's resolver, for a grant's TRUSTEE). Both are
`RuntimeException: ||The operation couldn't be performed because object '<identity>' couldn't be found on '<server>'.` over
a plain `System.Exception`. The cached module proxy (`tmpEXO_*.psm1`, read only) explains it: `Write-ErrorMessage` builds
`Exception("<stringId>|<ClassName>|<message>")` (both empty here, hence `||`), category `NotSpecified` unless the server
names one, reason `Exception` unless an `x-ExceptionType` header comes back, error id `[Server=...,RequestId=...,
TimeStamp=...]`, writes it from a nested function, and the caller's catch rethrows it (`throw $_`). So the caller gets a
RuntimeException a throw statement raised, which no structural test reads. A probe through this host's PowerShell 7 (no
Exchange) reproduced it exactly; a function's catch never sees its own WriteError's stop, which is why the stand-ins write
from a nested function too.

- **`Services/ExchangeServiceBase.cs` `IsNotFound(Exception ex, string? identity = null)`**: every structural test stays as
  it was - CommandNotFoundException excluded first; category ObjectNotFound; a `*NotFoundException` reason; a
  `*NotFoundException` identifier in the error id unless a throw statement raised it (the identifier test). Then, new:
  Exchange's own sentence, `couldn't be found` (`NotFoundSentence`, the fragment `ExchangeIdentityResolver` has read since
  July), in the record's details or its exception's message - **only when it is about the read's own object**: the
  sentence names `identity` (`'<identity>' couldn't be found`, or `"<identity>" couldn't be found`, the
  Get-MailboxAutoReplyConfiguration "Identity:" form of the 2026-08-18 audit trail), or names no object at all. A sentence
  that names another object - the dev line's trustee - is a failure like any other. With no identity given, a sentence that
  names an object is not an answer.
- **`ReadUnlessNotFound`** reads the object it asks about from its own command before invoking (`AskedIdentity`: the
  `-Identity` value, or the first `-ArgumentList` value of an on-premises read sent through `Invoke-Command`), because
  `InvokeOptional` clears the pipeline whatever happens.
- **The direct catch sites** pass what they asked about: the on-premises archive read (`ExchangeServiceBase`, the mailbox),
  Migration's cloud archive read and its excluded-group read (`MigrationService`), Recipient Lookup's archive read and its
  Get-Recipient catch (`RecipientLookupService`).
- Comments that said "never its text" or "by structure" alone are corrected where they now mislead (`ExchangeServiceBase`,
  `MigrationService`, `ConferenceRoomService`, `RecipientClassification`, `RecipientLookupService`).
- **The stand-in**: `MigrationStubExchange.NotFoundAsBareText` (the logged shape: no category, reason `Exception`, an error
  id naming no type, bare text over `System.Exception`) and `NotFoundNaming(other)` (the same sentence about another
  object); a lookup given a record marked `Rethrown` writes it from a nested `Write-StandInRecord` and rethrows it from its
  catch, as the module's proxy does. `ExchangeWriteHarness.MissingListsInBareText` does the same for Conference Rooms'
  `Get-DistributionGroup`. `TheBareTextStandIn_IsTheShapeTheLogsRecord` pins the stand-in to the log: a RuntimeException
  from a throw statement, its inner exactly `System.Exception`, the message, `NotSpecified`, reason `Exception`.

## Found while doing it, not fixed

- **Approval may still refuse a mailbox in a batch of many.** The one migration-batch not-found in the logs (dev
  `app-20260929.log`, "Failed to retrieve migration users for batch ...") reads `||The migration batch <name> can't be
  found.` - a different sentence, from `Get-MigrationUser -BatchId`. If `Get-MigrationBatch -Identity` answers the same
  way, approval of a mailbox with no batch named for it still refuses ("Could not tell whether ... is in a migration batch
  of its own"), visibly and before any write. Not accepted here: the brief names one sentence and no log shows what
  Get-MigrationBatch -Identity says. One dev approval of such a mailbox settles it.
- **Get-MigrationUser -Identity's own not-found wording is unlogged.** The eligibility fix rests on it using the sentence
  (the generic identity-resolution not-found does); if it does not, the check stays Undetermined - visible, never
  Eligible. The record's dev check (one ToCloud eligibility check of a mailbox not in a batch) settles it.
- **A third not-found sentence exists**: `||Couldn't find '<recipient>' as a recipient.` (prod Delegation Report, 12 rows
  since August). The Delegation Report does not decide by `IsNotFound`, and an error is the right answer there. Recorded.
