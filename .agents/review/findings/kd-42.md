## Approach

Re-read at `4b89ce16`:

- `ExchangeAdminWeb.Tests/ClickGateSource.cs:243` - `WalkCodeBody`'s fall-through branch, `statementStart = c is ';' or ':';`,
  makes every `)` a non-start, a header's included. In `if (x) <p>a } b</p>` the `<p>` then fails `:216`'s
  `c == '<' && statementStart && IsTagShape(blanked, i)`, the element's text is walked as C#, its `}` closes the body,
  and every comment after it in the body stays readable.
- `:349-350` - `BlankHtmlComments` skips every `<!--` inside an @code region (`if (regions.Any(r => r.Contains(at)))`
  / `continue;`), so an HTML comment in a render-fragment template (`@<tr> ... </tr>;`), which is markup, stays text.
  `:352` searches for the `-->` in `blanked`, which inside a region is the Roslyn view: there a `//` in a template
  comment's text is a C# comment, already blanked to the end of its line, `-->` included.

What changes:

1. **After a control-flow header, a statement starts.** `WalkCodeBody` recognises `if`, `else`, `foreach`, `for`,
   `while`, `do`, `using`, `lock` and `fixed` where a statement can begin (`StatementKeyword`). `else` and `do` leave a
   statement start; the others mark the next `(` as a header, and its matching `)` (a stack of parenthesis depths) is a
   statement start, so a tag-shaped `<` there opens markup. No other `)` is: `(limit) <b ? 1 : 2` still compares. A
   header is still walked character by character, so a comment inside one is still blanked.
2. **HTML comments in @code templates are blanked.** New `TemplatesIn` finds a region's templates: an `@<` at code level
   (not in a comment, which the view has already blanked, nor in a literal, skipped as one Roslyn token) through the end
   of its element (`EndOfElement`); one whose element does not end inside the region is not taken. `BlankHtmlComments`
   blanks a `<!--` inside a template through the first `-->` before the template ends, searched in the source; one that
   does not close there is left alone. Every other `<!--` in a region - a string's text - stays, as before.

## Known gaps

- The header extension reaches only text that is not a compiled page (RZ1008).
- A `//` or `/*` in a template's markup text is read by the region's Roslyn view as a C# comment and blanked
  (pre-existing, kd-12's view). If that hides the template's end tag the template is not taken and its HTML comments stay
  readable - a missed blanking, never blanked markup.
- Markup written straight into an @code method (the `RenderTreeBuilder __builder` style) is not an `@<` template and is
  not scanned; no component has one (`__builder` appears in none).
- Candidate, not fixed here (a separate finding): `BlankHtmlComments` resumes its search at `close + 4`, one character
  past the end of the comment it has just blanked, so a comment that starts immediately after another's `-->`
  (`<!-- a --><!-- b -->`) is missed - in the markup since kd-31, and in a template now, because the template path
  shares the loop. No component has `--><!--`.
