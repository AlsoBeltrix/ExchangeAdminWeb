### What changes

- Both refusal rows gain the aud-a28 fields - `refusedAt` "TicketValidation" and `mutationAttempted` false - and the
  presence row passes the captured `ticket` instead of `""`.
- **One deviation from the dispatched approach, deliberate.** It said to shape `RemoveServer` like authorize,
  `TicketPresence.Refusal(ticket) ?? await ServiceNow.ValidateTicketAsync(ticket)`. I kept the two branches instead.
  Collapsing them would replace this page's deauthorize-specific message - "A ticket number is required for
  deauthorization. Enter one in the Authorize form." - with the generic "Ticket validation failed: Ticket number is
  required", and that sentence is the more useful one here precisely because the ticket box is NOT on the
  confirmation the operator is looking at; it lives in the Authorize form above. The substance of the instruction -
  presence first by the shared rule, then ServiceNow, both refusals audited alike - holds either way: `RemoveServer`
  has checked presence through `TicketPresence` since kd-24, so only the evidence was missing, and that is what
  changes. Flagged for the supervisor to overrule if the shape matters more than the sentence.
- Guard: the page's existing reflection fixture, extended to assert both rows' fields and the submitted ticket.
- Mutation: the extras dropped from the presence row.
