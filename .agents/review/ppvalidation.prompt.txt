WHAT THE RANGE CONTAINS (two related work streams, ten commits)

Stream A - protected-principal resolution via Exchange (commits 6faa92d, 76bfead,
eb30786, 0eca01e). The app blocks mutating operations on "protected principals" (VIP
mailboxes, protected groups). Resolution was on-prem Active-Directory-only via a
Get-ADUser LDAP filter, which could not see: mailboxes addressed by a secondary SMTP
alias, mail-enabled groups, or cloud-only recipients. The alias gap was a live
protection bypass in two modules that treat NotFound as "not protected" and allow.
Resolution now falls back to Exchange Online (Get-Recipient), which returns the
canonical primary address; that address is re-resolved in AD so group/OU/pattern rules
apply.

Stream B - protected-principal admin input validation (commits e4c40d0, 4aa310e,
67f2412, 3f9cec8, 521bb6e). The admin page saved any typed string into the protected
list; the AD autocomplete only suggested and the add handlers never checked. Entries
are now validated against AD before being accepted, and already-saved entries that no
longer resolve are badged.

THE INVARIANTS THIS WORK RESTS ON - test each one adversarially

1. ABSENCE vs FAILURE. Throughout both streams, "the directory says no such object"
   and "the lookup could not run" must stay distinct. Collapsing them either
   un-protects a principal during an outage (stream A) or tells an admin their correct
   entry was a typo (stream B). Hunt for ANY path where a failed lookup can surface as
   an affirmative absence. Check: ExchangeIdentityResolver.ResolveRecipientAsync,
   ProtectedPrincipalService.ResolveWithExchangeFallbackAsync,
   ADDirectorySearchService.ValidateExists / ClassifyOutcome.

2. NO NEW ALLOW. Stream A must not make any operation succeed that previously denied,
   except the deliberate cloud-only branch. Resolved/Ambiguous/Unavailable must pass
   through from AD exactly as before. Verify the callers in PermissionValidator,
   ConferenceRoomProtectionGate and GroupManagementService.

3. THE INVERTED PAIR (deliberate, easy to mistake for a bug). A failed lookup REFUSES a
   new admin entry (ProtectedPrincipalEntryValidator.Decide) but stays SILENT about an
   existing one (ShouldFlagAsStale). Both derive from "a directory that did not answer
   is not evidence about the object" yet point opposite ways. Judge whether that
   reasoning holds, and whether the code actually implements it.

4. CLOUD-ONLY. A cloud-only principal gets a ResolvedDirectoryPrincipal with a null DN.
   Group and OU rules silently no-op on a null DN. The claim is that those rules are
   inapplicable (a cloud-only object cannot be an on-prem group member) rather than
   skipped. Check the claim and check that nothing else in CheckAsync misbehaves on a
   principal with null DN / null SamAccountName.

5. TEST VACUITY - look hard here. Two vacuous tests were already caught during this
   work and fixed; assume more may remain. Specifically: (a) tests gated on
   `if (!svc.IsAvailable) return;` silently skip on a host WITH RSAT installed, which
   this dev box has; (b) a test that early-returns when a fixture is missing is
   indistinguishable from a pass. See ADDirectorySearchServiceTests (pre-existing) and
   ADDirectoryLiveTests (new). Flag any test in the range that would still pass with
   its subject deliberately broken.

6. CONCURRENCY / UI. ADDirectorySearchService serializes on a single _runspaceLock with
   a 30s timeout, and this is a Blazor Server app where blocking the circuit freezes the
   user's page. AdminSettings.razor now calls ValidateExists on add, and sweeps every
   saved entry after first render. Check for circuit-blocking, races between a queued
   validation and a later one, and stale-state writes.

7. SECURITY. This is authorization-adjacent code. Validation deliberately runs under the
   app pool's ambient Windows identity, NOT the higher-privilege Delinea directory-read
   secret - an owner ruling on least privilege, given that read access is
   undifferentiated in this environment. Check for LDAP filter injection (note
   EscapeLdapFilter and the DOMAIN\ prefix stripping in NormalizeIdentity - consider a
   trailing backslash and other edge inputs), and for anything that would let an
   unvalidated or wrong value reach the protected list.
